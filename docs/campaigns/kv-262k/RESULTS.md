# K8V4 KV 格式 + 262K 上下文扩展实测（ac922, 2026-10-06）

四臂纯配置实验：生产配方（岛 3,3 + H + FIFO + MTP4，IQ3_XXS-MTP-Q8）只动 KV dtype 与 ctx。
源码零改动；fork: `sources/llama-v100-v3`（BF16 prefill 补丁默认开）；全部数字今日新鲜实测。

## 结论（TL;DR）

1. **K8V4 @262144 可用且 decode 无损**：TG 93.63 vs 基线 93.78（8K 口径，-0.2%）；64K 口径 83.37 vs 83.23（+0.2%）。逐位 parity 在 8K 与 64K 都通过——q4_0 V（Hadamard 旋转后）没有翻转任何一个贪心 token。
2. **代价在 prefill：-4~5%**（650.2→624.6 tok/s @8K；741.4→707.6 @64K）。臂 1（262K）与臂 2（132K）数字重合 → 是 V-q4_0 写路径的格式代价，与 ctx 无关。
3. **修正任务书里的显存预估**：262K K8V4 的 KV 全家桶实测 **3.51 GiB/卡**（不是预估的 ~2.2 GiB；主 KV 2496 MiB 而非 1658）。比现役 Q8_0/132K 的 2.15 GiB/卡**多 63%，不是更省**。但峰值显存 14.1/16.4 GiB，仍放得下（余量 ~2.3 GiB）。
4. **accept 率损失：测不出来**（量化上界 <~0.1）。合成基准 accept 饱和 1.000（重复段落 prompt，draft 全中，无区分度）；真实文本 accept 被续写类型混杂（同臂重复轮散布 ±0.09~0.14），四臂区间大面积重叠。
5. **生产切换建议：值，但按"花 4% prefill 换 2× 上下文"来定价，而不是按"省显存"**。若 prefill 吞吐敏感，备选是留在 Q8_0/132K。f16 KV 不可能上 262K（主 KV 需 6192 MiB/卡，全家桶 ~8.2 GiB/卡 + 权重超 16 GiB）。

## 一、实验设置

| 臂 | KV 参数 | ctx | 说明 |
|---|---|---|---|
| 0 | `--cache-type-k q8_0 --cache-type-v q8_0` | 132096 | 今日新鲜基线（= 生产配方） |
| 1 | `--cache-type-k q8_0 --cache-type-v q4_0` | **262144** | 主目标：K8V4 + 扩容 |
| 2 | `--cache-type-k q8_0 --cache-type-v q4_0` | 132096 | 隔离格式影响 |
| 3 | `--cache-type-k f16 --cache-type-v f16` | 132096 | accept 上界参照 |

- fork 没有 `--kv` 单参；**k8v4 的实际传法是 `--cache-type-k q8_0 --cache-type-v q4_0`**。Hadamard 旋转由"量化类型"自动触发（`llama-kv-cache.cpp`: `attn_rot_k/v = is_quantized(type) && head%64==0`），q8_0 时也开（K+Q 同旋转，注意力分数在精确算术下不变；V 存前旋转、输出后反旋转）。
- draft KV 四臂统一 q8_0（`--cache-type-k/v-draft`）——accept 差异只反映主 KV。
- 模型 `n_ctx_train = 262144`（原生 262K，无需 rope scaling）。
- 每臂流程：起服 → matrix_runner `1:8192` → `1:65536`（对照 `manifests/speed-bundle-single`，512-ID 逐位 parity）→ 真实文本 64K probe ×3。
- 启动器：`scripts/launch_kvtest_arm.sh` + `scripts/run_test_server_kvtest.sh`（生产两脚本的参数化副本，其余 setenv 逐字保留）；probe: `scripts/kvtest_realtext.py`。生产脚本与 fork 源码零改动。

## 二、四臂主表（合成基准，tok/s）

| 臂 | PP@8K | TG@8K | PP@64K | TG@64K | parity 8K | parity 64K | 合成 accept |
|---|---:|---:|---:|---:|---|---|---|
| 0 q8/q8 @132K | **650.2** | **93.78** | **741.4** | 83.23 | 逐位一致 | 逐位一致 | 1.000（饱和） |
| 1 k8v4 @262K | 624.6 (-3.9%) | 93.63 (-0.2%) | 707.6 (-4.6%) | 83.37 (+0.2%) | 逐位一致 | 逐位一致 | 1.000（饱和） |
| 2 k8v4 @132K | 624.7 (-3.9%) | 93.42 (-0.4%) | 709.0 (-4.4%) | 83.20 (-0.0%) | 逐位一致 | 逐位一致 | 1.000（饱和） |
| 3 f16 @132K | 637.0 (-2.0%) | 95.26 (**+1.6%**) | 720.0 (-2.9%) | 83.98 (+0.9%) | 逐位一致 | 逐位一致 | 1.000（饱和） |

判读：
- **parity：8 个 matrix case 全部逐位一致，零 token 翻转**——包括 q4_0 V 和 f16 对 q8/q8 参照。任务书担心的"部分翻转"没有出现，无需差异模式分析。
- PP：k8v4 一致性 -4%（两 ctx 相同 → 纯格式代价，V 量化写路径）。f16 也 -2%（写入路径同样有差）。
- TG：q8/q8 与 k8v4 打平；**f16 反而最快**（95.26，+1.6%）——V100 上 f16 V 的注意力读路径比 q8_0 反量化还快。
- 跨日漂移参照：speed-bundle-single（10-01 旧配方）自身是 PP 532.6/TG 78.85 @8K——今日臂 0 比它 +22%/+19%。臂间对比只用今日臂 0，协议正确。
- 262K 池本身零 decode 罚：臂 1 与臂 2 的 TG/PP 全线重合（2× 的池没有拖慢 64K 内的任何东西）。

主 KV 行格式：`size = X MiB (cells, 12 layers), K (ty): …, V (ty): …`

| 臂 | 主 KV MiB | 索引器 K | 稀疏索引表(f32) | draft (主+索引) | **KV 合计** | 主 KV 每 cell 每 layer |
|---|---:|---:|---:|---:|---:|---:|
| 0 q8/q8 @132K | 1644.75 (822.38+822.38) | 205.59 | 193.51 | 137.06+17.13 | **2198 MiB** | 1037.4 B |
| 2 k8v4 @132K | 1257.75 (822.38+435.38) | 205.59 | 193.51 | 137.06+17.13 | **1811 MiB** | 793.5 B |
| 1 k8v4 @262K | 2496.00 (1632.00+864.00) | 408.00 | 384.01 | 272.00+34.00 | **3594 MiB** | 793.5 B |

- k8v4 每 cell 省 **23.5%**（V q4_0 = q8_0 的 0.529 倍 + padding），与任务书 816 vs 1056B 口径一致（实测 793.5 vs 1037.4B）。
- **但 262K 是 1.985× cells → 主 KV 净增 52%**。任务书"≈1658MiB/卡、比现役还省"不成立：主 KV 实测 2496 MiB，全家桶 3.51 GiB/卡（现役 2.15 GiB）。
- f16 @132K 全家桶 3.73 GiB/卡（无 OOM，一次过，没触发 98304 回退）。f16 @262K 外推主 KV 6192 MiB/卡 → 不可行。

## 四、MTP accept 率（核心难题：测量本身）

### 合成基准：饱和，无区分度
matrix prompt 是固定段落重复 → MTP draft 全中，四臂 8 个 case 全部 `1.000 (408/408, mean len 5.00)`。只能证明"没掉到 1 以下"，不能量化损失。

### 真实文本 probe（64K 真语料 = README+docs+kv-cache/common/ggml 源码，冻结 token ids，512 token 贪心续写 ×3/臂）

| 轮 | 臂 | accept | TG | 续写族 |
|---|---|---:|---:|---|
| r2 | 0 q8/q8 | 0.428 | 46.8 | PROSE |
| r1 | 0 q8/q8 | 0.516 | 46.5 | PROSE |
| r3 | 0 q8/q8 | 0.752 | 66.3 | MDHDR |
| r1 | 1 k8v4@262K | 0.893 | 76.6 | MDHDR |
| r2 | 1 k8v4@262K | 0.888 | 74.8 | MDHDR |
| r3 | 1 k8v4@262K | 0.709 | 62.6 | MDHDR |
| r1 | 2 k8v4@132K | 0.804 | 68.6 | MDHDR |
| r2 | 2 k8v4@132K | 0.878 | 73.7 | MDHDR |
| r3 | 2 k8v4@132K | 0.870 | 72.1 | MDHDR |
| r1 | 3 f16 | 0.688 | 58.8 | PROSE |
| r2 | 3 f16 | 0.601 | 51.5 | PROSE |
| r3 | 3 f16 | 0.871 | 77.3 | PROSE |

**混杂因子（如实记录）**：贪心 + TP/NCCL 归约顺序 → 近并列 logit 轮间随机翻转 → 同臂同 prompt 的续写在第 10~20 个 token 内就分叉，掉进"散文续写"(PROSE，难 draft，accept 0.43~0.69) 或"markdown 标题流"(MDHDR，易 draft，accept 0.71~0.89)。accept 主要由掉进哪族决定，不由 KV dtype 决定。

族内对比：
- MDHDR 族：k8v4@262K 中位 0.888、k8v4@132K 中位 0.870 vs 基线 0.752（n=1）——k8v4 不低于基线。
- PROSE 族：f16 中位 0.688 vs 基线 0.428/0.516——f16"上界"名义反超基线，但 n=3 对 n=2 且族内散布 0.60~0.87，无统计意义。

**K8V4 accept 损失量化结论：未检出。** 同臂重复轮散布（±0.09~0.14）大于任何臂间中位差；在 n=3 下真实效应被界定在 <~0.1。方向上与 sglang 对照判断一致（K 精确保注意力分数，V 旋转后 q4 的伤害小）；更强的证据其实是第二节：q4_0 V 在 8K/64K 两个深度、共 1024 个贪心 token 上零翻转。per-position 接受率四臂形态一致（例如基线一轮 `(0.701, 0.581, 0.431, 0.347)`，逐位递减），无异常早衰。

## 五、262K 长文验证（臂 1）

- **池真实分配**：log 确认 `n_ctx = 262144`、主 KV `262144 cells` / 2496 MiB、draft `262144 cells`。64K prompt + 512 生成（66,048 cells）在池内正常服务。
- **TTFT（64K 真实文本，热服后）**：臂 1 = 93.4s vs 基线 90.3s（+3.4%，含 KV 池索引翻倍的影响，可接受）。f16 臂 92.0s。冷服第一发 141~250s（CUDA 图捕获，各臂皆然，非 262K 特有）。
- 64K 合成 case：臂 1 PP 707.6 vs 基线 741.4——与 8K 的 -3.9% 同源，无深度放大。
- **未做**：>200K 的满深度 prompt（另一会话的 prefill-parallel 实验在排队用卡，且 5 分钟级 prefill 会挤占其 3h 窗口）。池满深度行为（碎片、idx 表满载）留作切换前的一项 smoke。

## 六、生产切换建议

**值——按如下账本定价：**

| 项 | 变化 |
|---|---|
| decode 速度 | 无损（93.6 vs 93.8；64K 口径持平） |
| prefill 速度 | **-4~5%**（650→625 @8K，741→708 @64K） |
| 输出质量 | 合成 8K/64K 逐位一致；真实文本 accept 无可测损失（上界 <0.1，受测量方差约束） |
| 上下文 | 132K → **262K**（模型原生 n_ctx_train=262144，无 rope hack） |
| KV 显存 | 2.15 → 3.51 GiB/卡（**+63%**，不是预估的"更省"）；峰值 14.1/16.4 GiB（85.8%） |

- 切换动作：生产启动器两行——`AC922_TEST_CTX=262144` + KV 参数改 `--cache-type-v q4_0`（K 保持 q8_0）。建议直接给 `run_test_server.sh` 加 `AC922_TEST_KV_K/V` 两个 env（本次实验的 `run_test_server_kvtest.sh` 已验证该 diff，拷回即可）。
- 不切 f16：@262K 装不下；@132K 虽 TG +1.6%，但上下文不扩、KV +1.6 GiB/卡，无净收益。
- 风险清单：① 峰值 85.8% 单流健康、加并发 slot 前必须重算；② 满深度 262K prompt 未 smoke；③ 真实业务文本（非代码语料）的 accept 损失本次无法分离，建议上线后盯 server 日志 `draft acceptance` 一周。
