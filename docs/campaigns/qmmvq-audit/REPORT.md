## 2. 微基准（fork kernel 逐字提取，真实形状 × nc{1,5}）

方法：`nvcc -arch=sm_70 -O3 -use_fast_math`（=fork 构建旗标）；kernel 模板/vecdot/调参表 **逐字节取自 fork mmvq.cu/vecdotq.cuh**（`sed -n` 行区间提取，见 bench/）；L2 欺骗用 ≥24MB 权重复制品轮转（小形状 13-182 份）；stream 循环计时（本机 cudaGraph capture 损坏——空 kernel 也失败，已用最小程序证伪——故无 graph 数；R17 原位时间作交叉验证）。数据随机填充（计时对量化内容不敏感）。

**有效性交叉验证（bench vs R17 原位）**：iq2s_volta 31.4 vs 31.3µs（完全一致）；输出头 nc5 310 vs 312µs；moe Q2_0 38.9 vs 41.4；iq3s gu 52.8 vs 64.9；q6k ssm 13.4 vs 18.8。bench 系统性快 0-25%（原位 L2/TLB 更冷），量级与排序可信。

### 2.2 关键根因测量：块调度下限（空 kernel，V100 实测）

| grid 块数 | 空启动 µs | | grid | 空启动 µs |
|---|---|---|---|---|
| ≤1280 | **3.5** | | 5120 | 9.7 |
| 2560 | 5.6 | | 6400 | 11.8 |
| 3200 | 6.7 | | 12800 | **22.2** |
| | | | 82774 | **124-135** |

（与 block 内线程数 64-256 无关；>1280 后 ≈ 576 块/µs 线性）

**这改变 MoE 的判决性质**：
- moe Q2_0 down 实测 38.9µs 中 **~22µs 是纯块调度**（grid 12800×160 线程，每块只算 2 行×213 列——Q2_0 vdr=1/qi=2 → blocks_per_iter=16，而每行只有 4 个块，32 线程仅 8 线程有活，K 循环仅 1 次迭代）。带宽修复只能拿到 38.9→~24µs；**必须重组 grid（少块多活）才能到 ~6-10µs（4-6×）**。
- 输出头（grid 82774）实测 220µs 中下限 124-135µs 与内存时间 145.7MB/870=167µs 重叠——**76% 已接近该 grid 结构的实用上限**，重组（每块多行）上限 ~1.3×。
- 小 shexp（grid 96-128）5-6µs vs 下限 3.5µs：真实工作仅 ~2µs，**单 kernel 视角接近合理**，收益在融合（与相邻算子合并或 up/gate/down 三连发批处理），不在向量化。

## 3. 判决

| 家族 | 现状 %copy | 判决 | 对比 BF16 战役前(40-50%) |
|---|---|---|---|
| MoE 全家族（R17 1157ms, 12.3%） | **4-14%** | **大病**，但主因是 grid 碎+每 warp 工作量小+调度下限，次因才是访存模式 | 远差于 BF16 前值 |
| dense 大形状 K-quant/IQ4_XS（~815ms） | **20-47%** | **病**，与 BF16 前值同档；bf16 战役同款手法（流式+行分块）适用 | 持平略差 |
| dense IQ3_S | **13-20%** | **重病**：L1 查表解码瓶颈（同形状 Q6_K 是 37%）| 差 |
| 输出头 nc1（246ms） | **76-80%** | 接近上限，判活 | 好于 BF16 优化后 |
| 输出头 nc5（164ms） | **54%** | 可修（nc5 版本 312µs vs nc1×5=1045µs 已摊薄，重组 grid 可到 ~85%）| 持平 |
| dense 小 shexp（~370ms） | 名义 3-7%（受 3.5µs 下限） | 单核接近地板；收益只在融合/批处理 | 不适用 |

**端到端收益上界估算**（R17：mmvq 31.2% + moe 12.3% = 43.5% kernel 时间；标注：估算）：
- MoE（1262ms trace 总量）：grid 重组+向量化到 40-55% copy → **省 ~950-1050ms**
- dense 大形状（~815ms）→ 65-75% → 省 ~380-430ms
- 输出头 nc5 + 小 shexp 融合 → 省 ~100-200ms
- 合计 kernel 时间省 ~1500ms/3130ms ≈ **48%**；折 decode 全步（kernel 占 ~65%）：**理论上限 ~+18-20% decode 速度**；按 BF16 战役落地折扣（实现拿到 kernel 级收益的 ~50-60%），**现实预期 +9-12%**。

## 4. 改造方案草图（不修改 fork；下届战役提案）

1. **MoE 内核重组（最大单点，~950ms 池）**：弃"每块 2 行×全 K、每 warp 1 token"结构。改为每块 8 warp×256 线程，1 warp 连续流式扫 1 个 (expert,row-tile) 的全部 K 块（K=2560 → 10 个 256 块或 40 个 64 块，uint4×连读，ILP≥4），5 token 的 y 驻 shared（10×5×80 块×36B=144KB 超了 → y 只驻 5 token×213 列 ≈ 38KB 可行，或每块只做 1-2 expert）。grid 从 12800 → ~1280（下限 22.2→3.5µs）。参照 iq2s_volta 已证方向（同形状 31.4µs vs 通用 39.5-52.8µs，但只到 13%——它的 warp 仍逐 32 元素组散读，未流式）。
2. **dense 大形状**：直接复用 BF16 战役的 `kernel_sm70_bf16.cuh` 骨架（chooser/ROWS/K-split），把内积换成对应 vecdot：块内行是连续的量化块序列（Q6_K 210B/256el 块连排），uint4 流读 4×128bit 后就地解码可行；**注意与 BF16 不同**：每块先读 scale（块头）再读 payload，解码 ALU 密（Q6_K 每 256 元素 ~64 dp4a + 移位），48%→70%+ 需要每线程 2 行交错隐藏解码延迟。
3. **IQ3_S 专项**：查表（iq3s_grid 1024×8B）在 L1 命中时仍限速 → 表放 shared（fork 的 iq2s_volta 已这么干，grid_s[1024]）+ dp4a 路径，预期 20%→40%+。
4. **输出头 nc5**：grid 41387→rpb=2 已是 32 线程/块结构；改 4 行/块（grid ~10350，下限 ~18µs）+ nc5 y 驻 shared → 目标 85%（~171µs，省 ~45%/297 次×5 token 窗）。
5. **不值得做**：小 shexp 单核向量化（地板 3.5µs vs 现状 5-6µs）；输出头 nc1 重组（≤1.3×，246ms 池子只省 ~50ms）。
